# 维护长期必需品清单

此清单用于长期拥有或需要备齐的物品，例如水杯、笔记本电脑、电子琴、洗衣篮。它与消费品评价库和最低价清单完全分离：不记录评分、价格、门店或备注。

## 项目配置

- Supabase project ref：`rlyngocxosbmcylsxtvw`
- 前端只读；写入优先使用已连接并获授权的 Supabase 工具。
- 不索取、展示或保存 `service_role`/secret key。
- 用户提供物品照片时，仅用于识别名称、品牌和使用场景；不上传、保存或展示图片。

## 数据表：`essentials`

| 字段 | 类型 | 要求 |
| --- | --- | --- |
| `id` | uuid | 主键；数据库通过 `gen_random_uuid()` 自动生成 |
| `name` | text | 必填；物品的通用、可识别名称 |
| `brand` | text | 必填；正式品牌名，未知或不重要时使用 `Others` |
| `categories` | text[] | 必填；物品类型与零个或多个使用场景标签 |

数据库唯一约束为 `(name, brand)`。不要手动提供 `id`。

## 类型与场景标签

每件物品至少有一个类型标签；可另外添加使用场景标签。写入前删除重复值并按字母排序，保证数据稳定。

### 物品类型

- `personal-care`：个人护理
- `kitchen`：厨房
- `electronics`：电子设备
- `everyday-carry`：随身物品
- `documents`：证件
- `household`：生活用品
- `personal-items`：个人用品
- `storage`：收纳
- `medical`：医疗用品
- `appliances`：家电
- `instruments`：乐器

### 使用场景

- `home`：日常居家需要备齐。
- `travel`：旅行时需要携带。
- `move`：搬家时需要带走或在新住所补齐。

例如笔记本电脑为 `["electronics", "home", "travel", "move"]`。优先使用以上标签；没有合适的类型或场景时，先问用户是否新增标签，只有明确同意后才使用。

## 品牌规则

- 不复用 `brands` 表，也不创建品牌记录。
- 品牌能明确区分物品时，使用正式名称，例如 `Apple`、`Yamaha`。
- 无品牌、品牌未知或品牌对清单不重要时，必须写 `Others`。
- 不要把空字符串、`N/A`、`Unknown` 或随意描述当成品牌。

## 执行流程

### 1. 收集信息

从用户消息和（如有）物品照片中收集：

- 物品名称
- 品牌
- 一个或多个类型与场景标签

缺少物品名称或类型标签时，先询问。缺少品牌时，建议 `Others` 并请用户确认；不要猜测品牌。照片信息不清晰时，请用户补充。

### 2. 每次先读取完整清单

任何新增、更新或回答“旅行/搬家需要什么”前，必须执行 `SELECT * FROM essentials`。清单规模较小，不能只用精确名称查询。

- 规范化名称和品牌的大小写、首尾空格、连字符及常见标点后比较。
- 发现同名、同品牌或近似名称的候选项时，展示候选物品与场景。
- 不要因已有场景不同就创建重复物品；应先判断是否为同一件长期物品。

### 3. 新增或更新的判断

**匹配已有 `name + brand`：**

- 展示已有标签和拟增加的标签。
- 用户确认后，将新标签与旧标签合并、去重并更新 `categories`。
- 如果用户想移除标签，展示更新后的完整标签数组并要求确认；不得把数组更新为空或失去所有类型标签。

**无匹配记录：**

- 展示拟新增的 `name`、`brand`、`categories`。
- 等待用户明确确认后插入新记录。

**疑似但无法确认是否为同一物品：**

- 提示用户候选项和相似原因。
- 在用户确认前暂停写入；确认不同后才可新增。

### 4. 写入前确认

任何写操作前，展示以下表格并等待明确确认：

| 项目 | 拟写入值 |
| --- | --- |
| 操作 | 新增 / 增加标签 / 移除标签 |
| 物品 | `name` |
| 品牌 | `brand` |
| 类型与使用场景 | `categories` |

用户修改名称、品牌或场景后，重新读取全表并重新比对，再确认。

### 5. 写入与验证

用户确认后：

1. 再次 `SELECT * FROM essentials` 并复查目标记录。
2. 新增时插入记录，让数据库生成 UUID；更新时仅修改已确认的 `categories`。
3. 按 `id` 或 `name + brand` 重新查询，确认名称、品牌和场景与确认表一致。
4. 用 publishable/anon 身份进行前端等价 `SELECT`，确认 RLS 下可读取。

最后报告新增或更新的物品、品牌与完整标签列表。

## 场景清单查询

当用户说“我要旅行”“我要搬家”或“家里要补齐什么”时：

1. 先 `SELECT * FROM essentials`。
2. 分别筛选 `categories` 包含 `travel`、`move` 或 `home` 的记录。
3. 按名称列出对应物品与品牌；结果只基于用户维护的个人清单。
