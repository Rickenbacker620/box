# 维护手动航班票价表

这是个人维护的最低票价表，不是实时航班搜索或价格预测。只记录用户提供或明确确认的价格，不联网获取、补全或核对票价。

## 项目配置

- Supabase project ref：`rlyngocxosbmcylsxtvw`
- 前端只读；写入使用已连接并获授权的 Supabase 工具。
- 不索取、展示或保存 `service_role`/secret key。
- 用户提供票价截图时，只用于识别路线、航班号和价格；不上传、保存或展示截图。

## 数据表：`flight_fares`

| 字段 | 类型 | 要求 |
| --- | --- | --- |
| `id` | uuid | 主键；数据库通过 `gen_random_uuid()` 自动生成 |
| `route` | text | 必填；使用 `IAD - HND` 这类 IATA 三字码路线格式 |
| `flight_number` | text | 必填；例如 `UA 803`、`MU 586` |
| `lowest_price` | text | 必填；保留用户提供的最低价文字，例如 `544` 或 `139 + 50 (Carry on)` |

数据库唯一约束为 `(route, flight_number)`。不单独保存航司：航司已包含在航班号前缀中。不要手动提供 `id`。

## 执行流程

### 1. 收集信息

收集路线、航班号和最低价。航班号为 `N/A`、无法辨认或用户不想记录时，不新增记录。路线或航班号格式不明确时，先询问用户。

### 2. 每次先读取完整票价表

任何新增、修改或回答航班价格问题前，必须执行 `SELECT * FROM flight_fares`。清单规模较小，不能只用精确查询。

- 规范化路线中的空格与连字符，以及航班号中的空格和大小写后比较。
- 相同路线、相同航班号视为同一条记录。
- 同一路线但不同航班号必须保留为不同记录。

### 3. 新增或更新

若已有相同路线和航班号：展示现有价格与拟写入价格；只有用户明确确认后才更新 `lowest_price`。

若不存在：展示拟新增的路线、航班号和最低价，等待用户明确确认后插入。

### 4. 写入与验证

用户确认后：

1. 再次 `SELECT * FROM flight_fares` 复查目标记录。
2. 新增时让数据库生成 UUID；更新时只更新已确认的最低价。
3. 按路线和航班号重新查询，确认与确认表完全一致。
4. 用 publishable/anon 身份做一次前端等价 `SELECT`，确认 RLS 下可读取。

最后报告新增或更新的路线、航班号和最低价。

## 查询

回答“某条路线最低多少钱”时，先读取全表，列出该路线的所有航班号和手动记录的最低价，并明确说明结果不是实时网络价格。
